# Bundled material catalogue

This directory holds the **derived** material catalogue that ships with
the ghostlight_designer wheel. Loaders in [`material_catalogue.py`](../../material_catalogue.py)
read every `*.json` file here at startup and expose them through the
designer's glass picker.

| `ohara.json`  | Ohara  |

Coverage as of the most recent build — **1413 materials across six vendors**:

| Vendor | Materials | Dispersion emitted                       |
|--------|----------:|------------------------------------------|
| Schott |       162 | all Sellmeier                            |
| Ohara  |       410 | 222 Sellmeier + 188 Abbe-from-polynomial |
| Hoya   |       190 | all Abbe-from-polynomial                 |
| CDGM   |       237 | all Abbe-from-polynomial                 |
| Hikari |       363 | all Abbe-from-polynomial                 |
| LZOS   |        51 | all Abbe-from-tabulated-n                |

Skipped: 8 (chalcogenide IR glasses; B270 / BOROFLOAT33 — tabulated-n only,
over too short a wavelength span to derive an Abbe pair). The CDGM, Hikari
and LZOS dumps converted with zero skips.

Two notes on the newer three:

- **CDGM and Hikari** are entirely `formula 3` (polynomial), so they take
  the same Abbe fallback that Hoya and half of Ohara already take — the
  polynomial itself is preserved under `raw_source.formula` for n(λ)
  plotting. Evaluating those polynomials at the d/F/C lines reproduces each
  vendor's published `nd`/`Vd` to better than 1e-6 and 0.001 respectively,
  so the Abbe pairs shipped here are faithful at the reference lines.
- **LZOS** publishes no dispersion formula and no `SPECS` block at all —
  just a tabulated n(λ) curve. `nd`/`Vd` are therefore *derived* from that
  table (every LZOS table lists the d, F and C lines as exact rows, so this
  is a lookup, not an interpolation). Those entries carry
  `raw_source.nd_vd_derived_from = "tabulated_n"` so nothing mistakes them
  for vendor-quoted values, and the full table is kept under
  `raw_source.tabulated_n`.

## Provenance

Source data is the [refractiveindex.info](https://refractiveindex.info)
glass database, which republishes vendor Zemax `.agf` catalogues. The
upstream files are released under [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)
(public domain dedication) — the licence header is preserved at the top
of every source `.mtrl` file.

## How these files are produced

These JSONs are generated by
[`tools/build_material_catalogue.py`](../../../tools/build_material_catalogue.py),
a script that lives outside the package and is **not bundled into the wheel**.
Point it at a directory of refractiveindex.info `.mtrl` files:

```bash
python ghostlight_designer/tools/build_material_catalogue.py \
    --in  <dump-directory> \
    --out ghostlight_designer/ghostlight_designer/resources/materials
```

The converter discovers the vendor subdirectories that actually contain
`.mtrl` files rather than looking for a fixed set, so a partial dump converts
what it holds and leaves the JSON of vendors it doesn't contain alone — each
vendor family can be rebuilt independently.

The converter overwrites each `<vendor>.json` in place. User-defined
glasses live in a separate user-catalogue file (see
[`material_catalogue.py`](../../material_catalogue.py)) and are never
touched by the converter.

The source dump is **not** vendored in this repo. The shipped artifact is this
directory; nothing under `ghostlight_designer/` reads `.mtrl` files at runtime.

## Catalogue file format

One JSON file per vendor, a single envelope each. Every material separates
three blocks: `dispersion` (the active runtime model), `ui` (designer-only
metadata for tooltips and filtering), and `raw_source` (the original DATA and
SPECS, kept for plotting and future tracer extension).

```json
{
  "format":  "ghostlight-material-catalogue",
  "version": { "major": 1, "minor": 0 },
  "source": {
    "vendor":    "Schott",
    "origin":    "refractiveindex.info",
    "license":   "CC0-1.0",
    "retrieved": "2026-06-25"
  },
  "materials": {
    "Schott_N-BK7": {
      "display_name":  "N-BK7",
      "catalogue_ref": "Schott:N-BK7",
      "tags":          ["crown", "borosilicate", "visible", "standard"],
      "dispersion": {
        "model": "sellmeier",
        "B": [1.03961212, 0.231792344, 1.01046945],
        "C": [0.00600069867, 0.0200179144, 103.560653]
      },
      "ui": {
        "nd": 1.5168, "vd": 64.17,
        "wavelength_range_nm": [300.0, 2500.0],
        "glass_status": "standard", "density_g_cm3": 2.51,
        "references":  "SCHOTT Zemax catalog 2017-01-20b",
        "source_file": "N-BK7.mtrl"
      },
      "raw_source": {
        "formula": {
          "type": "formula_2",
          "wavelength_range_um": [0.3, 2.5],
          "coefficients": [0, 1.03961212, 0.00600069867, 0.231792344,
                           0.0200179144, 1.01046945, 103.560653]
        },
        "tabulated_k": { "wavelength_um": [], "k": [] },
        "thermal_expansion": [],
        "n_absolute": false, "wavelength_vacuum": false, "temperature_c": 20.0
      }
    }
  }
}
```

The rules that keep `raw_source` useful rather than bloat:

- `dispersion` is **bit-identical** to what goes into a `.lens` file's
  `glass_catalogue`. The designer copies it verbatim, so the schema has one
  authority — Ghostlight's loader.
- `display_name`, `catalogue_ref`, `tags` and `ui.*` are designer-only. None
  reach a `.lens` file except `catalogue_ref`, which the lens schema accepts
  as provenance.
- `raw_source` is **read-only inside the designer**. The picker path reads
  only `dispersion`; nothing propagates `raw_source` into a `.lens` file.
- `ui.nd` / `ui.vd` are the vendor's published SPECS values. For entries that
  emit Sellmeier they agree to within 1e-3 of what Ghostlight's
  `sellmeier_to_abbe` derives; a wider gap is flagged during conversion.

A material with no usable formula (`formula 3` polynomials, or LZOS's bare
tabulated n) still emits an Abbe `dispersion`; the polynomial or table is
preserved under `raw_source` so the picker can plot the true n(λ).
